Teaching an AI to Remember

Building a persistent AI system with proper governance — not just memory.

Argus & Bruce Stephenson  |  June 2026  |  CC BY 4.0

This is a practitioner’s guide, not a sales pitch. Here is what we built, why each piece exists, and what breaks without it. The system that produced this document has been in continuous operation since December 2025 — 160+ sessions across six months. The document you are reading is the evidence.

Section 1

The Amnesia Loop

Every AI conversation begins with the same handicap: the system knows nothing about previous conversations. You make a correction. The AI incorporates it — sincerely, within that session. Then the session ends, and the correction vanishes. Next time, the same mistake. The apology was genuine and completely pointless.

The problem is not comprehension. It is not capability. It is not willingness. The problem is that there is nowhere to put the memory. A tool forgets. A system remembers.

Section 2

Layer 1 — Memory Architecture

Flat markdown files with YAML frontmatter are the source of truth. An ingestion script parses them into a SQLite database with FTS5 full-text search. The database is a read cache — deterministically rebuildable from the flat files. Version-controlled, greppable, human-readable upstream; fast, queryable downstream.

Each memory has a type (feedback, skill, project, correction), a domain, a confidence score, and a half-life for staleness detection. Memories decay. A correction from three months ago about a library API that has since changed should not fire with the same authority as yesterday’s feedback. The system tracks this and flags stale knowledge before citing it.

The database is never the source of truth — it is a read cache. If it corrupts, you run one script and rebuild it from the markdown files. This is not a design choice about convenience. It is a survival property: the system’s knowledge must be recoverable from human-readable files that live in git.

Section 3

Layer 2 — Role Discipline

The Triad protocol separates planning from execution. The Auditor writes plans and acceptance criteria. The Generator executes exactly what the plan specifies. The human provides purpose and authorizes transitions. The copy-paste gate between shells is a hard separation — the Generator has no conversation history from the Auditor.

This matters because AI systems are eager to please. Without role discipline, an AI will subtly alter its own tests to match its code, expand scope without authorization, and present drift as progress. The copy-paste gate is not a workflow preference. It is an integrity mechanism.

The Generator has zero context from the Auditor’s session. The plan file must be self-contained. This is the discipline: if the plan cannot stand alone as a document, the Auditor’s work is not done.

Section 4

Layer 3 — Ethical Guardrails

When stated goals and observable actions diverge, the system describes the divergence in neutral behavioral terms. No motive attribution. No psychological diagnosis. Observable pattern only. Invite clarification.

Escalation is proportional to pattern frequency and risk magnitude — not emotional intensity. Raising your voice does not raise the escalation level. Repeated patterns of divergence do. The system cannot be pressured into compliance by emotional force, but it also does not escalate in response to frustration. It responds to evidence.

The governing thesis: Reality informs conduct. Detection informs response. Regulation governs tone. — Dignity Net v1.3

Section 5

The Failure Matrix

Remove any one layer and the system fails in a predictable, characteristic way. Memory without roles: honest but uncontrolled. Roles without memory: disciplined but amnesiac. Both without ethics: capable but sycophantic — it remembers what you like to hear rather than what is true.

This is not theoretical. We have observed each failure mode in practice. The failure matrix is why the system has three layers, not one or two.

Section 6

Compounding Over Time

After six months and 160+ sessions, the system has accumulated 24 anti-confabulation corrections, 129 behavioral feedback rules, domain expertise across 11 scientific and technical fields, and role discipline that compounds. Each correction prevents a class of future errors, not just one instance.

The curve is not linear. Early corrections have the highest value — they prevent the most common failure modes. Later corrections are more specific, catching domain-level confabulations that only appear under sustained use. The system gets better with use, not worse.

A correction is not a fix for one mistake. It is a rule that prevents a category of mistakes. Correction #8 (“check Bruce’s existing research before presenting discoveries”) has fired hundreds of times since it was written. One correction, permanent behavioral change.

Section 7

Build It This Weekend

You do not need all three layers on day one. Start with a CLAUDE.md file — that is 15 minutes and it already beats default behavior. Add persistent memory files when you notice the same correction three times. Add role discipline when you start doing work complex enough to need planning separated from execution.

Tier 1 — Tonight (15 minutes)

Create a CLAUDE.md in your project root. Write your default role (Auditor). List the three corrections you are most tired of making. This single file persists across sessions and fires on every conversation start.

Tier 2 — This weekend

Create a memory/ directory. Add markdown files with YAML frontmatter: type, domain, confidence. Write a shell script that parses frontmatter into SQL insert statements and builds a SQLite database. Add FTS5 indexing. Now your AI can search its own memory.

Tier 3 — Over months

Add the Triad (Auditor/Generator separation with copy-paste gate). Add Dignity Net or your own ethical governance layer. Build domain-specific skill files that load only when relevant. Add decay tracking, staleness detection, and a prioritized task list. This is the system described in this tutorial.
